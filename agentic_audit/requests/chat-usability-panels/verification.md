# Implementation and verification

First working implementation committed as 84b11ce. Completed all six requested recommendations:

1. /settings shows an arrow-key menu for model, timeout, turn limit, and prompt/context/file byte limits. Selecting a field places the composer cursor after its command prefix. Values are validated against Config, saved atomically to the correct TOML section, and applied immediately; unrelated sections/comments are preserved. HTTP adapters are recreated with the updated config. Changing models opens a fresh conversation and preserves original identities of old conversations/runs. No provider/model network discovery is performed.
2. Timeout errors automatically open an arrow-key recovery menu. /recover reopens it manually, including after reopening an unfinished run. Actions retry a pending reply or unfinished workflow, edit timeout, or export logs. Coding recovery offers plan review rather than automatic approval. Pending messages survive settings and exports.
3. Persistent request/run stage strip displays selected request, run identifier, and stage; existing next-action hint stays visible. Stage comes from run state even for older audits lacking progress snapshots.
4. Last submitted prompt byte count is recorded in provider-call events and progress snapshots. UI selects the latest actual prompt across chat/run scopes and shows its configured budget. Input/output token totals come from provider reports; missing dimensions are unavailable. Byte counts describe the harness representation, not exact tokenizer counts or transport payload size.
5. /history QUERY searches saved conversation text, pending messages, recorded errors, and request bundles without model calls. Results distinguish chats from requests and support arrow-key selection to reopen/select. Results are capped at 50; malformed event lines are skipped. Unprepared requests offer /prepare. Recovery and review state reset on conversation/request changes.
6. /plan and /run open a scrollable saved-plan panel; /review reopens it. Tab focuses the panel, Escape closes it, and the composer supports advice, revision, and explicit /approve. It displays the actual plan, including its supplied affected files, verification, and risks, rather than invented summaries. Existing reviewed-plan hash, identity, current-context, and explicit approval checks remain authoritative.
